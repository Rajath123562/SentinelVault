## 2. Minute-by-Minute Live Demo Walkthrough

### ⏱️ 0:00 – 0:25: Introduction, Login & Dataset Selection
* **Narrative**:
  > *"Judges, hospitals and financial institutions need statistical insights from sensitive customer records, but direct raw-data access causes privacy leaks. Welcome to SentinelVault. Our tagline is: Analyze Data. Don't Expose It."*
* **Action**:
  1. Show the SentinelVault login screen. Note the server-authoritative 5-attempt lockout security.
  2. Enter credentials: `analyst_user` / `AnalystPass2026!`.
  3. Click **Sign In**.
  4. Point to the authenticated session badge showing role: `ANALYST`.
  5. Select the **Synthetic Health Records** dataset (500 records, privacy unit: `patient_id`).

---

### ⏱️ 0:25 – 0:55: Query Validation & Differential Privacy Execution
* **Narrative**:
  > *"Analysts never submit raw SQL or query sensitive identifiers like names or SSNs. The backend gateway enforces strict allowlists and bounds every individual's contribution to at most one."*
* **Action**:
  1. In the query builder, select field: `diagnosis_category`.
  2. Select value: `cardiovascular`.
  3. Select privacy budget: $\epsilon = 0.5$.
  4. Click **Preview & Check Policy**. Show the pre-release policy check passed and budget verified.
  5. Click **Execute Differential Privacy Release**.
  6. The backend draws real Laplace noise via IBM `diffprivlib` and returns the noisy count.

---

### ⏱️ 0:55 – 1:20: Protected Result & Verifiable Privacy Receipt
* **Narrative**:
  > *"Notice that the exact ground-truth count is never exposed to the analyst. Furthermore, every release generates a cryptographically verifiable Privacy Receipt."*
* **Action**:
  1. Click **View Cryptographic Privacy Receipt**.
  2. Highlight the receipt fields:
     - `receipt_id`: Unique identifier.
     - `mechanism`: `Laplace (IBM diffprivlib)`.
     - `epsilon_spent`: `0.5`.
     - `signature`: Ed25519 digital signature generated by the gateway keypair.
     - `audit_entry_hash`: Cryptographic link to the immutable hash chain.

---

### ⏱️ 1:20 – 1:45: Privacy Budget Ledger & Repeat-Query Caching
* **Narrative**:
  > *"Differential privacy budgets are limited. SentinelVault tracks cumulative expenditure transactionally using micro-epsilon integer arithmetic to prevent floating-point drift."*
* **Action**:
  1. Point to the **Cumulative Privacy Budget** card: remaining budget has decreased from 5.0 to 4.5.
  2. Click **Back to Query Builder** and resubmit the **exact same query**.
  3. Point to the result: `is_cached: True`, `epsilon_spent: 0.0`.
  4. The budget remains at 4.5 because identical queries reuse committed releases without double spending.

---

### ⏱️ 1:45 – 2:10: Budget Exhaustion Enforcement (Fail-Closed)
* **Narrative**:
  > *"What happens when an analyst tries to overspend? Let's demonstrate our fail-closed budget enforcement."*
* **Action**:
  1. Show that when total requests exceed the remaining allowance (or if remaining budget is depleted), the gateway rejects the query.
  2. Demonstrate that the backend returns **HTTP 429 Too Many Requests: Privacy budget exhausted**.
  3. Point out that no noisy count or private data was leaked when the budget check failed.

---

### ⏱️ 2:10 – 2:35: Zero-Trust Defense & Raw Data Access Rejection
* **Narrative**:
  > *"What if an attacker tries to bypass the UI, inject forged roles, or request raw rows via direct API calls?"*
* **Action**:
  1. Open the browser DevTools network tab or terminal.
  2. Show that direct requests to `/api/v1/query/release` or direct attempts to dump raw rows return **HTTP 403 Forbidden**.
  3. Click the **Security Events** tab in the UI:
     - Show real-time SIEM logs recording all authentication events, blocked attempts, and rate limits.

---

  > *"Every release is bound to an immutable SHA-256 hash chain with Ed25519 signatures. Anyone with auditor privileges can verify the ledger."*

  2. Click **Re-verify Audit Ledger**.
  3. Point to the green verification badge: `AUDIT CHAIN INTEGRITY VERIFIED (SHA-256 + Ed25519)`.
  4. Show the **Empirical Utility Benchmark Table**: empirical MAE and RMSE scaling inversely with $\epsilon$ across 50 trials.
  5. Point to the honest disclosure box:
     - `DEMO ACCOUNTING ACTIVE — OFFICIAL CONFORMANCE NOT VERIFIED`
     - `OFFICIAL EMPIRICAL RISK EVALUATION NOT CONFIGURED`
* **Closing**:
  > *"SentinelVault proves that institutions can unlock critical analytical insights from sensitive records without ever exposing them. Thank you."*
